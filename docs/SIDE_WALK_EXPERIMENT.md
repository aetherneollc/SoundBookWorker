# M2 全景侧身走路受控试验

## 结论

**本试验不建议接入生产渲染链路。** 保留 M1 的“中景走路 + 小步挪位”取景规避规则，不修改 `renderer/rig_mesh.py`、`renderer/director.py` 或 Godot 播放器。

原因不是原型不能运行，而是出片复查未过：

- 仓库和相邻 `SoundBookCF/public/media` 中没有找到可用的真实正侧面角色图，示例 `char-000c8a14f0f22053-*.png` 也没有本地原图；现有可用角色纹理是正面/近正面。
- CPU 补画能生成像素，但不能还原被手臂遮住的拉链、色块边界和服装线稿。
- 真实像素代理仍是被横向压缩的正面脸和正面服装，不是身份、发型、衣服都锁定的侧面设计稿。把它当作全景侧身素材会直接产生角色一致性问题。
- 六帧条带中，手臂移开后可见补画区域的细节丢失和软糊；手臂枢轴、手部轨迹也有明显的纸片拼接感。

## 试验输入

默认运行包含两组：

1. `controlled_profile`：程序绘制的正侧面平涂角色。手臂前层和未遮挡躯干真值已知，用于量化补画误差。
2. `real_pixel_proxy`：使用本地真实纹理 `media/m0_real_gate/linlan_1011/texture.png`，从对应 rig 的 `arm_r` 三角形提取手臂，再把它重排到躯干前。该组只用于检验复杂服装像素的补画，不冒充真实侧面参考图。

脚本也支持传入真实侧身图和显式掩码：

```text
python tools/experiment_side_walk.py --input side.png --arm-mask arm.png --torso-mask torso.png
```

若提供 `--lama-onnx model.onnx`，会优先尝试 CPU LaMa；模型缺失、格式不兼容或推理失败时，自动回退到 OpenCV。此次本机没有可用的 LaMa 大权重，因此没有把 LaMa 质量计入结论。

## 实现

- 近侧手臂输出为独立 RGBA 前层；躯干及其余身体输出为背层。
- 补画区是“手臂掩码 ∩ 预期躯干掩码”，并仅在该区域扩边。
- 无 LaMa 时同时评估 `cv2.INPAINT_TELEA` 与 `cv2.INPAINT_NS`，再以补画边缘的局部平涂色板修复深层像素，选择误差较低者。
- 六帧循环对前层手臂绕肩旋转，并对两腿做反相摆动和轻微身体起伏。
- 指标使用已知隐藏躯干作真值；`colour_mae_0_255` 越低越好，`edge_smoothness_error` 越低越好，`gradient_retention` 接近 1 最好。

## 实测数据

本次 Windows CPU 单次结果如下；耗时会随机器负载波动。

### 受控正侧面

- 选中方法：`cv2-navier-stokes+flat-palette`
- 选中方法耗时：`37.477 ms`
- TELEA / NS 候选耗时：`59.134 / 37.477 ms`
- 两种候选完整评估耗时：`101.004 ms`
- 手臂遮挡区占躯干：`56.333%`
- 颜色 MAE：`41.455 / 255`
- 边缘平滑度误差：`64.126`
- 梯度保留率：`1.018`
- 判定：**穿帮**。隐藏服装颜色、白色横线和轮廓连续性未恢复。

### 真实角色像素代理

- 选中方法：`cv2-navier-stokes+flat-palette`
- 选中方法耗时：`1512.101 ms`
- TELEA / NS 候选耗时：`1656.717 / 1512.101 ms`
- 两种候选完整评估耗时：`3265.814 ms`
- 手臂遮挡区占躯干：`20.205%`
- 颜色 MAE：`26.239 / 255`
- 边缘平滑度误差：`52.797`
- 梯度保留率：`0.220`
- 判定：**穿帮且糊成一团**。补画区只保留约 22% 的原始边缘能量，拉链、腰带、橙蓝色块和褶皱无法从周边像素推回。

## 视觉自查

已用图像读取工具逐帧查看 `media/m2_side_walk/side_walk_strip.png`，并查看带补画边界的 `side_walk_diagnostics.png`。

- 受控组确实形成了六帧摆臂迈步，证明前后层和 CPU 路径可运行；但第 2、3、5、6 帧手臂移开时，躯干的白色横线、橙色饰条和深色轮廓不连续，手臂转动也有脱节感。
- 真实像素组的脸和服装仍明显朝向镜头，只是轮廓被压窄；这不是可交付的正侧面角色。摆臂时手落到腹股沟附近，补画的胸腹区域丢失服装结构并变软，远看仍能察觉异常。
- 因此“算法可运行”不等于“可出片”。当前结果不能支撑全景侧身走路。

只有在获得同一角色、同一服装的锁定正侧面设计图，并配套人工确认的手臂掩码或干净躯干背板后，才值得重新试验；届时补画应作为离线预处理缓存，而不是逐镜头 CPU 运行。
